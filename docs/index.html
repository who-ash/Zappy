Hand-made demo videos are…
slow and stale.

Without Zappy

  • Screen recorders compress hard, so small UI text comes out soft and blurry.
  • Every UI change means recording, editing and voicing the whole thing again.
  • Zooms, cursor highlights and captions are keyframed by hand in an editor.
  • Voiceover means a quiet room, a decent mic and a lot of retakes.
  • Real emails and names on screen slip through to a public video.

With Zappy

  • Every repaint is saved as a full-quality frame and rendered up to 4K.
  • A flow is a short YAML file. When the UI changes, run make again.
  • Cursor, click ripples and a smooth zoom onto each step, automatically.
  • AI voiceover (OpenAI or Sarvam), burned-in captions and a matching .srt.
  • Private data is blurred by CSS selector before a single frame is captured.

Zappy is everything your screen recorder should have been.

How it works

From prompt to mp4

Zappy is an agent skill. Your agent reads your app, writes the script and checks the result before handing it over.

1

Ask your agent

“/zappy make a demo of inviting a teammate.” It reads your routes and the labels of your buttons.

2

It writes a spec

Plain steps with selectors built from what users see, plus one line of narration per step.

3

Zappy films and renders

It drives Chromium against your dev server, captures every frame and renders with Remotion.

4

Your agent checks the stills

Loading screens, bad zooms and wrong captions get fixed and remade before you see anything.

zappy/specs/invite.yaml
title: Invite a teammate
startUrl: /settings/members
auth: admin
blur: [".account-email"]
steps:
  - action: click
    selector: { role: button, name: Invite member }
    narration: To add a colleague, press Invite member.
  - action: fill
    selector: { label: Email }
    value: priya@example.com
    narration: Enter their work email.
  - action: click
    selector: { role: button, name: Send invite }
    narration: Send it, and they get an email to join.
# style: promo  →  headlines, stickers, beat cuts

Questions? We've got answers.

What do I need to run it?

Node 22 or later and your web app running locally. The first run installs Playwright's Chromium, and the first render downloads Remotion's headless Chrome (about 140 MB).

Does it record my production site?

No. Point it at a local or staging dev server with demo data. A before: command can reset that data before each recording.

Which voices can I use?

Sarvam (Bulbul v3) or OpenAI (gpt-4o-mini-tts), using your own API key. Set tts.provider: none for a captions-only video with no key at all. Clips are cached, so a re-render only pays for lines you changed.

What about flows behind a login?

Run zappy login admin <url> once and sign in by hand. The session is saved locally (git-ignored), and specs use it with auth: admin.

Can it make vertical videos for social?

Yes. Set style: promo with format: vertical or square for a short, music-led clip with headlines and stickers.

How do I keep private data out of the video?

Use fictional demo data where you can. For anything else, list CSS selectors under blur and those elements are blurred on every page before capture.

Is it free?

Yes, MIT licensed. The only cost is TTS usage on your own key, if you turn voice on.
